#### what must be extracted from a random page scan or photograph or any image from the archive:

1. was it created during a dig
2. was it created in a lab after the dig
3. OCRed labels present on it (structured or in prose)
4. number of objects on it:
  - **1** one instance of one object
  - **N** one instance of many objects
  - **1a, 1b, ... 1n** many instances of one object

Notes from Opus 5.5 before any runs:

- **Test pages:** the comparison should use the fold-1 test pages (4,795),
- **Routing:** the image describer above is the first concrete "further processor". Pages labelled `PHOTO`, `PHOTO_L`, `DRAW` and `DRAW_L` would go to it.


- **Prompt:** it reuses keyword-extract's prompt template and vocabulary. The vocabulary has no term for "made in a lab", so dig vs lab needs a short list of its own.
- **Linked document:** it can give the answer away, so each run is scored with and without it.


- **Annotations:** there are no annotated images for these fields yet. 100–200 pages annotated by ARÚP/ARÚB would be enough to start. Who could do it?


- **Hardware:** a DGX Spark has 128 GB of memory, so about 100 GB of weights is the practical limit per unit. Models of 100–150 GB need two linked units or 4-bit weights. Bigger ones can go to the Grace Hopper machine (Pavel's note in ufal/atrium-project#22)
