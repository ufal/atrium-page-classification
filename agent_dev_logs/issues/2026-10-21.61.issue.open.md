# [\#61 Issue](https://github.com/ufal/atrium-page-classification/issues/61) `open`: Directory runs: an unreadable image shifts later predictions onto the wrong files
**Labels**: `bug`, `development`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-10-21 07:59](https://github.com/ufal/atrium-page-classification/issues/61):

`custom_collate` drops an image that fails to load, but `dataframe_results` pairs predictions with `test_images` by position (`run.py` directory branch, `parallel_best.py`). Every image after the bad one gets its neighbour's prediction, the last one is lost, and nothing reports it. With `--no-inner`, any non-image file in the folder triggers it.

Also: with `-tn 1`, `infer_dataloader` returns class indices, so `SCORE-1` holds the class number, not a probability. The service avoids this with `max(topn, 2)`.

Fix: carry each item's index through the collate, return predictions aligned with the inputs, and log failed images as skips in the paradata. For `-tn 1`, return (index, probability) pairs like the top-N path. Test: a directory with one unreadable file in the middle.
