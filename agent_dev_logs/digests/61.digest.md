## What the issue reports

Two silent errors in batch inference, both found while writing the Galaxy wrapper (atrium-project#66):

1. **Shifted predictions.** `custom_collate` drops an image that fails to load, but `dataframe_results` pairs the
   remaining predictions with the file list by position. Every image after the bad one gets its neighbour's
   prediction, the last one is lost, and nothing says so. With `--no-inner`, any non-image file in the folder
   triggers it.
2. **The top-1 score.** With `-tn 1`, `infer_dataloader` returns class indices, so `SCORE-1` holds the class
   number, not a probability. The service avoided this with `max(topn, 2)`.

The issue names the fix: carry each item's index through the collate, return predictions aligned with the
inputs, log failed images as skips in the paradata, and give `-tn 1` the same (class, probability) pairs as
top-N. The test: a directory with one unreadable file in the middle.

| `parallel_best.py:430`, `:472`           | the parallel and sequential `--best` paths, the same pairing                     |
| `classifier.py:407`, `infer_dataloader`  | the top-1 branch returns `logits.argmax(-1).tolist()`: class numbers, not scores |
| `classifier.py:353`, `top_n_predictions` | the single-image path failed for `top_n=1`                                       |
| `service/inference.py:151`               | `internal_topn = max(topn, 2)`: the service's guard against the top-1 branch     |

Training was not affected: the Trainer uses `custom_collate` as well, but it pairs nothing with file names.

## Why it matters now

- **The papers.** The milestone is CAA Proceedings. The `vX.4` re-run on the LINDAT test sets that the user
  announced on atrium-project#15 runs `run.py` on directories; its numbers go into the CAA paper's Table 2
  (atrium-project#13, Decision A) and the classifier paper. That run needs this fix.
- **The service.** `/predict_document` and `/predict_image` were not affected (one image per request, and the
  `max(topn, 2)` guard). `predict_directory` was: an unreadable page shifted the others.
- **Galaxy.** The draft wrapper on atrium-project#66 pins `1.9.5-beta`, which has the bug, and guards against
  both errors: it opens every input first and fails the job naming any unreadable file, and it asks for at least
  two categories per page. Its README says "a page-classification issue, to be opened": that is this issue. The
  guards can go once it pins a fixed release.
