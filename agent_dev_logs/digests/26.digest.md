## 🎯 Goal
Package the page classifier as an **agent skill** modeled on
[`honzas83/uwebasr-skill`](https://github.com/honzas83/uwebasr-skill): a `SKILL.md`
(YAML frontmatter + agent guidelines) plus a **zero-dependency stdlib client** wrapping the
existing FastAPI service — curated knowledge about how to *call* the service well, not a new service.

## 🔍 The uwebasr-skill pattern (four ingredients)
1. **Zero-dep Python client** (stdlib `urllib` + `mimetypes` multipart; agent can `curl -O` one file).
2. **`SKILL.md`** — frontmatter + agent guidelines: model selection, when to ask vs. guess, output
   formats, error-handling playbooks (e.g. retry on 503, then report backend busy).
3. **Multi-agent install** — Claude Code (`~/.claude/skills/`), Codex (`~/.codex/skills/`),
   Antigravity via `AGENTS.md`.
4. **Citations baked in** — CLARIN/LINDAT acknowledgements (here: `CITATION.cff`, ATRIUM funding,
   LINDAT dataset handle — all already exist).

## ✅ Why the mapping is ~1:1
- `service/api.py` already exposes `/predict_image`, `/predict_document` (multipage PDF), `/info`
  (+ `frontend-lindat` variant) — the analogue of `uwebasr.zcu.cz`.
- The `v1.x`–`v5.x` revision matrix is exactly the "which model do I pick" knowledge SKILL.md
  encodes (prefer `v4.3`/best-5 ensemble; `-tn 5` for ambiguous pages; the #15 lesson that
  ~24/229 ambiguous samples flip between model generations = calibration knowledge the agent
  should carry — *surface top-N with scores instead of asserting top-1*).
- Structured top-N output (CSV/JSON) ≈ their format-selection guidelines.

## 📐 Packaging decision — a branch bundling server + client + skill
Since LINDAT is not live, a **branch** (`agent-skill`) that bundles **server + client + skill
wrapper** is the honest packaging: the skill must know how to *stand up* the server itself, then
talk to it as a client. `service/inference.py` imports `classifier.py` / `ensemble.py` /
`model_registry.py` (full torch/transformers/timm stack), so the server side cannot be pruned
below: `SKILL.md`, trimmed `README.md`, `LICENSE`/`CITATION.cff`, `scripts/atrium_classify.py`
(NEW, stdlib-only) + `scripts/serve.sh`, `service/`, the four server modules + `utils.py`,
`atrium_paradata.py`/`para_licenses.py` (provenance intact), `setup/`, Docker files, and `run.py`
(model download only). **Dropped**: `data_scripts/`, training/eval docs, `parallel_best.py`,
`yolo_classifier.py`, sweeps, `tests/` (maybe a minimal client test), `agent_dev_logs/`
(stays on `test`/hub), most of `small_data_samples` (keep 2–3 images as smoke fixtures).

## 🔌 Two-phase workflow in SKILL.md (the structural difference from uwebasr-skill)
- **Phase 1 — ensure server up**: `GET /info` (default `http://localhost:8000`); else
  `docker compose up -d` (CPU) / `docker-compose.gpu.yml` (GPU), fallback
  `setup_api_service.sh` + uvicorn; poll `/info` with a timeout playbook. Warn about first-run
  HF weight downloads (~300 MB–1.2 GB per revision) so the agent doesn't declare failure early.
- **Phase 2 — classify (pure client)**: `atrium_classify.py page.png` → `/predict_image`;
  `doc.pdf` → `/predict_document`; `--model vX.Y`, `--top-n N`, CSV/JSON output;
  `--base-url` + `ATRIUM_PC_URL` env override — the identical client works unchanged the day
  kosarko's LINDAT deployment exists.
- Paradata note: server-side inference stays logged via `atrium_paradata.py`, so provenance is
  preserved even when an agent is the caller.
