## 🧭 Where it stands — 2026-11-06

### What the candidates are

| Model                                              | Size                  | Backbone        | Images                                                         | Serving                                                    | Licence    |
|:---------------------------------------------------|:----------------------|:----------------|:---------------------------------------------------------------|:-----------------------------------------------------------|:-----------|
| `Cloudflare/clef`                                  | 27B                   | Qwen3.8-27B     | yes                                                            | SGLang `lmsysorg/sglang:dev-clef`; the card ran on 1×H200  | Apache-2.0 |
| `Cloudflare/clef-flash`                            | 9B                    | Qwen3.5-9B      | yes                                                            | as Clef                                                    | Apache-2.0 |
| `StrandsAgents/strands-decider-2B-qwen3.5-v1-2610` | 1.9B (LoRA + 1M head) | Qwen3.5-2B-Base | experimental (`[vision]` extra, `transformers` ≥ 5.18)         | `strands-decider serve`: 127.0.0.1, no authentication      | Apache-2.0 |

- **One prefill pass, no generation.** A request is a state (text, JSON, up to 4 images) plus up to 64 typed
  questions:
  - `choice`: 2–255 options with descriptions;
  - `noul`: yes or no;
  - `score`: an ordered list.
- **The answers:** a probability per option, plus `confidence`. The output cannot leave the schema, but it can still
  be wrong.
- **Limits that matter here:**
  - Clef's `encode_record` caps input at 16,384 tokens by default, and image tokens count. Scans must be downscaled.
  - Early image requests were slow (seconds).
- **What the guide says against using an LDM:** a stable, labelled, high-volume task, which the page classifier is.
  It also lists exact rules, arithmetic and sub-50 ms paths.
  - It recommends tuning confidence thresholds on one's own labelled data, a shadow period, and a thin wrapper so
    that providers can be swapped.

### Track 1: LDMs on the page categories

- **11 labels**, defined in [`docs/reference/categories.md`](../../docs/reference/categories.md). The order of
  `CATEGORIES` in `model_registry.py` is bound to the checkpoints and must not change.
- **Comparable baseline:** the fold-1 test partition (4,795 pages), held out for both models.
  - `v1.4` (EfficientNetV2-M): 95.87 % top-1, 99.90 % top-3.
  - `v4.4` (RegNetY-160): 95.81 % top-1, 99.79 % top-3.
  - Unseen documents: 95.60 / 95.19 %.
  - Gaps within ±0.6 points are not reportable.
- **Known hard pairs:** `TEXT_T` → `TEXT` (recall 87–92 %), `LINE_HW` → `LINE_T` (4–9 %).
- **Three tasks** (the plan's B1–B3):
  - **B1: standalone, 11 options.** This is the control.
  - **B2: cascade.** The CNN answers every page; under a CNN confidence threshold τ, the LDM picks among the CNN's
    top 3.
    - τ is taken from the raw softmax table (`--raw`), not from the renormalised `SCORE-1`.
  - **B3: routes.** Four yes/no questions: OCR, HTR, tables, image description.
    - Their gold follows from the 11 true labels through the hub's next-step table.
    - Their baseline is the routes derived from the CNN's label.
- **Shared client:** `decision_client.py` (written here 11-06, not pushed; standard library only).
  - It validates every answer and never raises.
  - It reports status, lane, latency and the question-set digest.
  - It computes Brier, ECE, coverage against error and McNemar.

### The three other repositories

Each has an issue of its own, opened 11-06 under [atrium-project#83](https://github.com/ufal/atrium-project/issues/83): ocr-postprocess#10, digital-convert#8, keyword-extract#3.

- **ocr-postprocess:** every line goes through one rule cascade (`determine_category`, `text_util.py`).
  - Its uncertain populations are documented:
    - short lines without Czech diacritics (about 26,000 garbage lines read `Clear`);
    - red flags that fire without a conviction;
    - the Noisy/Trash boundary (`Trash` recall 12–27 %).
  - A gold set of 2,067 labelled lines and an adoption gate exist.
  - The categories are frozen for the pilot, so the LDM runs in shadow mode, writing a sidecar table.
- **digital-convert:** `/describe` already reports per page a text layer, the classifier's label, a quality score
  and a route. _(superseded 11-11: `/describe` is not used in the pipeline, H11; the route is the pipeline's step)_
  - The LDM adds a type from AMČR's `dokument_typ` (41 terms with `api.aiscr.cz` URIs; 32 apply to PDF pages), read
    from the rendered pages alone (since 11-09).
  - The record has no field for it, and `pages[].category` belongs to this repository, so the type stays in the
    report.
  - A `document-type` scheme needs AMČR's agreement.
- **keyword-extract:** #2's generative prompt is 58,260 tokens; at 16k only ~1,100 of the 4,711 terms reach the
  model, and constrained decoding produced forced labels.
  - A descent (meta-text, facet, group, then the terms' own tree; `choice` ≤ 255 + `none_of_these`) keeps every
    answer in the list (D2) and reaches the whole vocabulary.
  - Only one node exceeds 255 children and is chunked.
  - Clef shares Qwen3.8-27B with #2's default model.

## ⚠️ Limits

- Benchmarks are vendor-reported (Decision Index, JevBench). Only local results on archive pages decide anything.
- Use the typed interface. Keep the per-option probabilities, `invalid` answers and timeouts. Never parse free text.
- Thresholds belong to one model revision and one wording. They are set on dev and frozen before test.
- OCR text sent as state is untrusted input. A decision is advisory and never authorises an irreversible step.
- Hosted inference (Workers AI, OpenRouter) needs a data-governance check before any archival image or text leaves
  the cluster.
- No production taxonomy, registry, API, record or default changes in this issue.
