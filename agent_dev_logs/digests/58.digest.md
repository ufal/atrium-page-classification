**Status**: 🧪 **Exploration opened; no runs reported yet.** The request is to compare Large Decision Models (LDMs) on the current page-category taxonomy and on an extended set aligned with the next processing steps, using the existing datasets / cluster. No candidate model, evaluation slice, extended taxonomy, runtime measurements, or results have been committed to the issue.

## 🎯 Goal

Find out whether a structured-output decision model is useful for ATRIUM page classification and/or downstream processor routing. The first experiment should establish a reproducible baseline against the current image classifiers; the second should test a separately versioned extension derived from documented processing needs. This is exploratory: an LDM should not replace the production models merely because it is newer or more general-purpose.

## 🧭 Where it stands — 2026-10-20

- **The production task currently has 11 categories.** The definitions are in the README's [Categories section](https://github.com/ufal/atrium-page-classification/blob/test/README.md#categories-), and the training-order binding is in [`model_registry.py`](https://github.com/ufal/atrium-page-classification/blob/test/model_registry.py). The order in `CATEGORIES` is load-bearing: reordering it can silently relabel the existing checkpoints. This experiment must not alter that list or existing checkpoint labels.
- **Current image-model baseline:** the released `v*.4` set is used by `--best` / service `version=all`; `v4.4` (`regnety_160`) is also a useful single-model baseline. The baseline must be rerun on exactly the same evaluation samples as the LDMs rather than comparing unrelated headline scores from different dataset revisions.
- **Dataset/reproducibility constraint:** the README describes the current `v*.4` generation as trained on 38,307 pages from 37,316 PDFs. The repository also supports explicit fold CSVs, and the research paper has described a fixed held-out set of 5,449 pages. Before choosing the final evaluation slice, verify which split and dataset revision the staged cluster data actually represents, and keep it fixed across all models.
- **Potential LDM candidates:** Cloudflare's open-weight [`Clef`](https://huggingface.co/Cloudflare/clef) and [`Clef-Flash`](https://huggingface.co/Cloudflare/clef-flash) model cards support image input and typed decisions with per-option probabilities; [`Clef-omni`](https://huggingface.co/Cloudflare/clef-omni) is another multimodal candidate. The cards and runtime support evolve quickly, so pin exact model revisions and record the checked versions rather than relying on the issue body's launch-era parameter descriptions. The official weights are listed under Apache-2.0, but that does not remove data-governance constraints on uploading archival images to hosted inference.
- **Runtime is a feasibility gate.** This repo's standard setup pins PyTorch 2.7.1 and `transformers<5`; the current Clef model card documents testing with PyTorch 2.11 and `transformers` 5.10.2 on an H200. Test a separate environment / Slurm allocation first. Do not upgrade the production environment to accommodate the experiment without a separate compatibility decision.
- **Taxonomy extension is not defined yet.** It should be derived from the next processing steps that actually exist or are planned, then recorded as a versioned crosswalk. Preserve the original page-category label separately from the recommended processing route where one-to-one mapping would be misleading.

## 🧪 Experiment shape

1. **Feasibility smoke test:** load one candidate model, classify a tiny stratified set, confirm image preprocessing and typed-schema output, capture VRAM/RAM, startup cost, latency and failure behaviour.
2. **Current taxonomy:** ask for one of the existing 11 labels using a controlled `choice` schema and explicit descriptions; evaluate against the same frozen labelled set used for the conventional baseline.
3. **Extended taxonomy / routing:** agree on the expanded category definitions or a category-plus-route schema with downstream owners. Identify which labels can be derived from existing annotations and which require new human adjudication. Evaluate only against verified ground truth; predictions must not be used to manufacture gold labels.
4. **Comparison:** measure accuracy, macro-F1 / balanced accuracy, per-class precision and recall, confusion matrix, confidence calibration, latency, throughput, resource use and failures. Keep prompt/schema variants controlled and record all model and data revisions.
5. **Decision note:** report where LDMs match or improve on the current ensemble, where they fail, whether the extended schema is genuinely more actionable, and whether further work is justified.

## ⚠️ Important limits

- Scores on Artificial Analysis' Decision Index are general benchmarks, not evidence of accuracy on historical page images. The local page-classification experiment is the deciding evidence.
- Clef is a decision model: use its typed decision / probability interface rather than treating generated free text as a class label. Preserve the raw per-option probabilities and invalid/error outcomes.
- If a hosted endpoint is considered, confirm that the selected archival images may be sent off-cluster before using real collection data. Prefer local weights for the first reproducible experiment where the available hardware allows it.
- Extended labels should correspond to explicit, documented processor actions. Do not create arbitrary fine-grained classes solely to give a model more options, and do not expand the production schema as part of this issue without a separate decision.
