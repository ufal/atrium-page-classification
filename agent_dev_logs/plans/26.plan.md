# Strategy — Issue #26: agent-skill branch for page classifier prediction

> Issue [\#26](https://github.com/ufal/atrium-page-classification/issues/26) · Labels: `documentation`, `enhancement`, `development` · **Status: ✍️ In progress — design settled; branch [`agent-skill`](https://github.com/ufal/atrium-page-classification/tree/agent-skill) created 2026-07-12 with cleaned-up files**

## Context
Package the classifier as an **agent skill** following the
[`honzas83/uwebasr-skill`](https://github.com/honzas83/uwebasr-skill) pattern: `SKILL.md`
(frontmatter + agent guidelines) + a **stdlib-only client** for the existing FastAPI service.
Because LINDAT is not live yet, the `agent-skill` branch bundles **server + client + skill
wrapper** — the skill teaches a two-phase workflow (ensure-server-up, then classify) and keeps
strict client discipline so the same client/guidelines work unchanged once a public LINDAT
endpoint exists (`--base-url` / `ATRIUM_PC_URL` flip only).

## Strategic actions
1. **Verify the branch manifest** against the issue's file list: keep `SKILL.md`, trimmed
   `README.md`, `LICENSE`/`CITATION.cff`, `scripts/`, `service/`, `classifier.py`, `ensemble.py`,
   `model_registry.py`, `utils.py`, `atrium_paradata.py`, `para_licenses.py`, `setup/`,
   Docker files, `run.py` (model download only); drop `data_scripts/`, `parallel_best.py`,
   `yolo_classifier.py`, sweeps, training/eval doc sections, `agent_dev_logs/`.
2. **Write the client** (`scripts/atrium_classify.py`): stdlib multipart upload; file-type routing
   (`.png/.jpg` → `/predict_image`, `.pdf` → `/predict_document`); `--base-url` +
   `ATRIUM_PC_URL`; top-N table (CSV) / raw JSON output; 503-retry with agent-facing failure text.
3. **Write `SKILL.md`**: frontmatter (`name`, `description`) + guidelines encoding what only the
   team knows — category semantics (Text/Drawing/Table/…), prefer `v4.3`/best-5, `-tn 5` on
   ambiguous archival pages ("don't guess — surface top-N with scores"), first-run weight-download
   latency, citation/acknowledgement block.
4. **Wire the lifecycle**: `serve.sh` (venv/docker up + `/info` poll with timeout); document
   Phase 1/Phase 2 in SKILL.md.
5. **Install docs** for the three agent ecosystems; smoke-test the skill end-to-end (start server,
   classify a fixture image and a small PDF, check paradata log written).

## Verification / done-criteria
- On a clean machine: `curl -O` (or clone the branch), run `serve.sh`, then
  `python3 scripts/atrium_classify.py fixture.png` returns a top-N table with scores — no pip
  installs on the client side.
- `SKILL.md` loads as a valid skill in Claude Code (`~/.claude/skills/`) and the agent can
  complete the two-phase workflow unaided.
- Paradata JSON written by the server for a skill-driven request (provenance preserved).
