# Strategy — Issue [#61](https://github.com/ufal/atrium-page-classification/issues/61): Directory runs: an unreadable image shifts later predictions onto the wrong files

**Status**: 🔧 **Implemented and tested on the working branch.** Left: the push, then a release (the maintainer's
step).

## The fix, as implemented

**One index per image, from the dataset to the table.**
- `classifier.py`:
  - `ImageDataset.__getitem__` returns the image's dataset `index` with its pixels (`:603`);
  - **`inference_collate`** (`:102`) wraps `custom_collate` and keeps the indices of the images that loaded. It is
    used for inference only: training keeps `custom_collate`, because the Trainer passes every collated key to
    the model;
  - `infer_dataloader` (`:404`) returns one entry per dataset item, in dataset order: `None` for an image that
    did not load. It warns when fewer predictions than items came back.
- `utils.py`:
  - **`keep_readable`** (`:102`) drops the `None` entries from the file, prediction, score and label lists
    together, and returns the dropped files;
  - `dataframe_results` (`:118`) refuses lists of different lengths (`ValueError`), skips a stray `None` with a
    warning, and accepts a bare class index (`as_pairs`, `:91`);
  - `confusion_plot` (`:276`) skips `None` the same way.
- `run.py`: every path that writes a table goes through `keep_readable` and logs each dropped file to the
  paradata with `log_skip(path, "unreadable image")`. These are the directory run (`:869`), the chunked run
  (`:923`), the folds test (`:511`), the folds loop (`:599`) and the evaluation (`:704`).
- `parallel_best.py`: the parallel loop aligns its predictions by `indices` (`:424`); the sequential path uses
  `keep_readable` and the paradata (`:468`).
- `service/inference.py`, `predict_directory`: an unreadable page gives an empty result for that page; the
  ensemble leaves out empty per-model results.

**One scoring rule for every N.**
- `classifier.topn_pairs` (`:118`) returns (class, probability) pairs, with the probabilities renormalised over
  the best max(N, 2) classes. This is the service's existing rule, so `-tn 1` and the API's `topn=1` agree.
- `top_n_predictions` (`:381`) and `infer_dataloader` use it. So do the YOLO models (`yolo_classifier.py`).
- `-tn 1` now writes the best class's share of the best two as `SCORE-1`. The README's score note says so.

## Tests

`tests/test_inference_alignment.py` (9 tests) runs the real dataloader and `infer_dataloader` with a stub model
whose answer is the image's colour, so a shifted pairing shows as a wrong category:
- an unreadable page in the middle of a directory: every other page keeps its own category, and the bad one is
  reported;
- a batch in which no image loads;
- `-tn 1` gives a probability in [0, 1];
- the single-image top-1 path;
- `topn_pairs` against a hand-computed case;
- `inference_collate` carries the indices; the Trainer's collate does not;
- a length mismatch raises;
- `confusion_plot` skips `None`.
