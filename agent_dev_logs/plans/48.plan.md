# Strategy — Issue #48: Ratify two model-registry defaults

> Issue [\#48](https://github.com/ufal/atrium-page-classification/issues/48) · Labels: `question` · Milestone: Q4 [WP3: Conclusion of Semantic Harmonization] · **Status: 🆕 Just opened, no discussion yet**

## Context
Despite the title, the issue as filed asks only **one** question: whether `--best` should move
from v*.3 to v*.4. (A second item — the unmerged CLIP-variant branch — was part of the original
draft for this issue but was not included when it was actually opened; it is noted here as a
possible follow-up, not treated as in scope.) This is a pure ratification with no code blocked
behind it, but "decision-only" doesn't mean "no work" — the decision needs evidence to be worth
recording, and none currently exists in this repo.

## Strategic actions

### A — Gather the comparison before deciding
Run (or locate, if already run informally and just not recorded) the same evaluation used to
validate v*.3 originally against the v*.4 revisions — same test set, same metrics. Without this,
"ratify v*.4" is a guess dressed as a decision.

### B — If v*.4 is ratified
Update `REVISION_BEST_MODELS` in `model_registry.py` to point at the v*.4 entries, bump the repo
version, and note the change in `CONTRIBUTING.md`'s release table (matching this repo's existing
convention for documenting registry changes).

### C — If v*.3 is kept
Replace the current comment ("kept on v*.3 for now") with one stating the actual reason and,
ideally, a condition under which it should be revisited — a comment that says "for now" with no
revisit trigger is exactly how this kind of decision goes stale silently.

### D — Flag the CLIP-variant branch separately, if still wanted
If the unmerged CLIP-variant work (99.14% benchmark, no registry entry) should still be tracked,
file it as its own issue rather than folding it into this one after the fact — this issue is
already closeable once A–C are done.
