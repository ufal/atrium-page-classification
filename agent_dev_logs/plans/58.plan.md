## Context

The classifier has a mature, image-only baseline: 11 labels whose `model_registry.CATEGORIES` order is bound to the
checkpoints. Its only held-out figures are per fold. Each `vX.4` model was scored on the test partition of the fold it
trained on, and the ensemble has none (`docs/evaluation/results.md`).

**What a decision model is.** It reads a *state* (text or JSON, plus images) and a set of typed questions in one
prefill pass. It returns a probability for every allowed option and generates no text.
- Question types:
  - `choice`: 2–255 options; `criteria` maps each option id to a description, or to null.
  - `noul`: yes or no.
  - `score`: an ordered list.
- A `choice` answer carries `choice`, `probabilities` and `confidence`; a `noul` answer carries P(true).
- A request holds at most 64 questions and 4 images.
- The output cannot leave the schema, but it can still pick the wrong option.

## Phase 0: the shared client and the servers

**The client: `decision_client.py`**, at this repository's root.
- **Dependencies:** the standard library and `requests`. Pillow is imported lazily, for images only. No torch.
- **Builders:** `choice()`, `noul()` and `score()`. They check: 2–255 options, at most 64 questions, at most 4
  images, unique ids.
- **`image_data_uri(img, max_side=1024)`:** resizes and encodes as JPEG. A large scan otherwise fills the context.
- **`DecisionClient(url, model, timeout_s, retries).decide(state, questions, images)`:** returns a `Decision`.
  - **It never raises.** Statuses: `ok`, `invalid`, `timeout`, `error`, `rejected`, `not_configured`. The status set
    follows digital-convert's stage connector (`service/stages.py:_post`).
  - Each call records its latency and `usage.input_tokens`.
- **Strict validation:** a choice outside the options, or probabilities that do not cover them or do not sum to about
  1, gives `invalid`. It is counted, never repaired.
- **`lane(answer, accept_at, review_below)`:** returns `accept`, `escalate` or `review`. The thresholds are set on dev
  data, per model and per question wording; they do not transfer.
- **`schema_digest(questions)`:** the SHA-256 of the canonical JSON of a question set. It serves as the prompt
  version.
- **Metrics, shared so the four repositories report alike:** Brier, ECE (10 bins), coverage against error,
  `pick_threshold(target_error)` and an exact McNemar.
- **`--selftest`:** runs against an in-process fake `/v1/systemone`, the way the hub's selftests run.

**Question sets** are versioned JSON (`decisions/<name>.v<N>.json`). Their criteria text is generated from the
vendored `atrium_vocab._PAGE_CATEGORY_DEFS`, so the definitions exist once.

**Copies.**
- ocr-postprocess, digital-convert and keyword-extract copy the file to their root and pin it in
  `tests/test_vendored_decision_parity.py` (`VENDORED` SHA-256 plus `ADOPTED`), the way `text_formats.py` and
  `teitok_read.py` are pinned.
- One row goes into the hub's `docs/shared_components.md`.
- The callers' `vendored-from` names this repository.

**Settings** (in the consumers' `.env.example` once a service reads them): `DECISION_MODEL_URL`,
`DECISION_MODEL_NAME`, `DECISION_TIMEOUT_S`. With no URL, the status is `not_configured` and nothing changes.

**Servers: the internal endpoint first (11-06).** Pavel's machine on ÚFAL's internal network serves Clef as
`clef-oQ8e`.
- It is reached through `DECISION_MODEL_URL` and `DECISION_MODEL_NAME=clef-oQ8e`. The host is never written in a
  public repository.
- **Record:**
  - the route that answers (`/v1/systemone` is assumed, as in oMLX PR 4315);
  - the server software and version;
  - the build and its quantisation;
  - the model's source revision.
- **It is one shared machine,** also holding a generative model. Latency and throughput are measured on it, not
  assumed. CI never calls it; CI uses the selftest's fake server.
- **It is outside the cluster.** The published LINDAT pages may go there. Other archive data waits for motyc's answer on
  the hub umbrella ([plan](https://github.com/ufal/atrium-project/blob/test/agent_dev_logs/plans/decision_models.plan.md)).

**Servers on the cluster** (`supplementary/scripts/decide_server_job.sh`, a Slurm template like `eval_vX4_job.sh`).
These are for Clef in bf16, for Clef-Flash, for Strands, and for any data that must stay on the cluster.
- Clef and Clef-Flash run through SGLang; Strands runs through `strands-decider serve`.
- Record: the image digest or package versions, the model's Hugging Face revision SHA, the GPU, the dtype, the
  memory, the resources.
- Hosted inference (Workers AI, OpenRouter) is not used. Archive images do not leave the cluster without a
  data-governance check.

**Paradata.** A `setup/para_config.txt` row per model (Apache-2.0, `conditional`). The run's `config` holds:
`decision_model`, `decision_revision`, `decision_schema_digest`, the thresholds.

## Track 1: LDMs on the page categories

### Phase A: freeze inputs, prove the runtime

1. Record: the tested commit, model ids and exact revisions, card dates, dtype or quantisation, server and versions,
   GPU and memory, Slurm resources.
2. Probe Clef on the internal endpoint first (Phase 0). The first request is the card's own example; the second, one
   fold-1 training page through `images`. That shows whether the endpoint takes images as the card's Python API does.
   - Record the route, the server and its version, and the build (`clef-oQ8e`; confirm the quantisation).
   - Check that the cluster nodes reach it.
   - The SGLang server on the cluster repeats the same two requests when it starts.
3. Run a smoke set of 3–5 pages per label, from the fold-1 **training** partition, not its test pages. Verify:
   - typed output, probability extraction and the `invalid` count;
   - the link from each answer to its file, and resume;
   - the latency at three image sizes (long side 768, 1024, 1536 px).
4. Measure cold load apart from steady-state latency, and peak memory.
5. Then Clef-Flash (not on the internal endpoint as of 11-06). Then Strands: first check whether its vision extra installs and answers. If it does not, Strands
   is marked "not applicable to page images" and its turn comes in ocr-postprocess, on text.

### Phase B: three tasks

Experiment CLI `decide_pages.py`, outside `service/`, with its own `requirements_decide.txt`.
- Inputs: images or a folds CSV.
- Output, `DECIDE_RAW.csv`: `FILE`, `PAGE`, one column per option probability, `choice`, `confidence`, `lane`,
  `status`, `latency_ms`, `schema_digest`. `utils.confusion_plot` and `data_scripts/eval_by_document_overlap.py` read it
  as they read `TOP-N_EVAL`.

**B1. The 11 labels, standalone (control).** `DRAW`, `DRAW_L`, `LINE_HW`, `LINE_P`, `LINE_T`, `PHOTO`, `PHOTO_L`,
`TEXT`, `TEXT_HW`, `TEXT_P`, `TEXT_T`.
- One typed `choice`, zero-shot. Criteria come from `docs/reference/categories.md`.
- The ids always map to these names; `CATEGORIES` is never reordered.

**B2. The cascade (the shape that could ship).**
- The CNN answers every page. When its top-1 probability is below τ, the LDM chooses among the CNN's top 3 labels
  only.
  - The probability is taken from the **raw** table (`--raw`, the full softmax). It is not taken from `SCORE-1`,
    which `classifier.topn_pairs` renormalises over the best classes.
  - Top-3 holds the true label on 99.90 % (`v1.4`) and 99.79 % (`v4.4`) of the fold-1 test pages.
- Report:
  - how many pages are deferred;
  - on the deferred pages, those the LDM fixes against those it breaks;
  - the net top-1;
  - the time per deferred page.
- τ is set on dev, from the coverage-against-error curve.
- **Why this shape:** the CNN is already at ~96 % and cheaper. The LDM is worth its cost only where the CNN is unsure.

**B3. Routes: the processor-aware extension.** Four `noul` questions, asked together:

| Route                     | Question (draft)                                                        | Gold from the true label                                        |
|---------------------------|-------------------------------------------------------------------------|-----------------------------------------------------------------|
| `route_ocr`               | Does the page carry printed or typewritten text to read?                | `TEXT`, `TEXT_P`, `TEXT_T`, `LINE_P`, `LINE_T`                  |
| `route_htr`               | Does the page carry handwritten text to read?                           | `TEXT`, `TEXT_HW`, `LINE_HW`                                    |
| `route_tables`            | Is any part of the page a table, a form or a tabular legend?            | `LINE_HW`, `LINE_P`, `LINE_T`, `DRAW_L`, `PHOTO_L`              |
| `route_image_description` | Is a photograph or a drawing the page's main content?                   | `DRAW`, `DRAW_L`, `PHOTO`, `PHOTO_L`                            |

- **Yes/no, not one `choice`:** a page can need several processors. `DRAW_L` needs both image and table extraction.
- **The gold costs nothing:** it follows from each page's true label through the hub's next-step table
  (`docs_site/workflows/page-classification.md`, "What each category suggests doing next").
  - Captions on `DRAW`/`PHOTO` pages ("through OCR, if any") are not in the gold: the label does not say whether
    there is one.
- **The comparison:** the LDM's routes against the routes derived from the CNN's label. The gain is where the two
  route sets differ.
- `route_image_description` is the track-2 describer, the first concrete "further processor" (10-29).
- Keep `page_category` (one of the 11) apart from the routes. A route is not a content class.

### Phase C: fix the evaluation set and baselines

1. **Use the fold-1 test partition** (4,795 pages, from the [LINDAT record](http://hdl.handle.net/20.500.12800/1-6184)
   split). It is held out for both `v1.4` and `v4.4`. Record its manifest and checksum.
2. **Use the fold-1 dev partition** for criteria wording, τ and the lanes. Freeze them before test.
3. **Do not use the 5,449-page set.** Most of its pages are training pages (`docs/evaluation/results.md`).
4. **Baselines:** rerun `v1.4` and `v4.4` on exactly these files with `--raw`. Reproduce 95.87 / 95.81 % before any
   LDM figure is reported. The `--best` ensemble may be run for context, labelled as having no held-out figure.
5. **Report the unseen-document subset separately** (95.60 / 95.19 % in results.md).
6. **No leakage:** no test pages as examples, and no rewording after looking at test errors.

### Phase D: run the decision models

Run them in order: **Clef**, then **Clef-Flash**, then **Strands** where Phase A found it applicable.
- One fixed zero-shot question set per task.
- At most one predeclared ablation on dev: concise against full criteria, and the image size.
- Typed interface only: no free text is parsed into labels.

### Phase E: evaluate

- **B1:**
  - top-1, balanced accuracy, macro-F1, per-class P/R/F1 and the confusion matrix;
  - in particular the weak pairs, `TEXT_T` read as `TEXT` (recall 87–92 %) and `LINE_HW` read as `LINE_T` (4–9 %).
- **B2:**
  - the fixed/broken count on the deferred pages;
  - the net top-1 against `v1.4` and `v4.4`, with an exact McNemar on the same pages. Differences inside ±0.6
    points are not claimed.
- **B3:** per-route F1 and exact route-set match, for the LDM and for the CNN-derived routes.
- **Calibration:** Brier and ECE per question, and coverage against error for the `review` lane.
- **Operations:**
  - cold start, median/p95 latency, pages per second, peak memory;
  - `invalid` answers, timeouts and retries: counted, never dropped.
- A per-document breakdown where ids exist.

## Track 2: structured description of archive images

### Phase F: output schema and prompt

1. **Schema (experiment JSON, not a record block):**

   ```json
   {
     "capture_context": "dig | post_dig_lab | other | unknown",
     "capture_context_confidence": 0.0,
     "labels": [{"text": "…", "kv": {"key": "value"}, "bbox": [0, 0, 0, 0]}],
     "object_count_pattern": "1 | N | 1a..1n",
     "object_count": 0,
     "description": "…",
     "terms": [{"term": "…", "facet": "Artefact", "uri": "…"}],
     "objects": [{"term": "…", "instance": "1a", "bbox": [0, 0, 0, 0]}]
   }
   ```

   `1` = one instance of one object; `N` = one instance each of several objects; `1a…1n` = several instances or views
   of one object (`objects[].instance` carries the letter).
2. **Prompt:** a `system_prompt.txt`-style block file loaded with keyword-extract's `prompt_template.py` format, with
   flags for optional blocks.
   - Role, then the task, then the rules: JSON only, terms only from the list, `unknown` allowed.
   - The vocabulary is injected after its header from `data_samples/vocab/union_nested.json`, restricted to the
     facets that describe objects: Artefact, Material, Feature, Finds Context, Chronology.
   - Plus the new `capture_context` list with definitions, and an output template like `prompts/output_template.json`.
   - Vendor or pin the prompt module rather than importing keyword-extract's tree.
3. **Inputs:** one or more images of the same item (a decision request takes at most four). The linked document's
   description and text are an optional block, switched by a flag.
4. **Closed fields by an LDM:** `capture_context` (`choice`) and `object_count_pattern` (`choice`) are also asked
   as decision questions through the Phase 0 client. Compare them with the VLM's answers to the same questions.

### Phase G: gold set

- Select pages predicted `PHOTO`, `PHOTO_L`, `DRAW` or `DRAW_L` from the dev/test partitions. Draw a stratified
  sample across sources and categories, sized by annotation capacity (start at ~100–200 images).
- Annotators (ARÚP/ARÚB): `capture_context`, label text (+ KV), object count pattern and count, object boxes with
  vocabulary terms. Keep a written rule sheet and measure agreement on a double-annotated batch.
- Never use model output as gold. Record the annotation tool, the guidelines version and the checksum.

### Phase H: runs and metrics

- **Runs:** with and without the linked document (the leakage check), per model, pinned.
- **Metrics:**
  - `capture_context` and `object_count_pattern`: accuracy, macro-F1, confusion matrix, and calibration for the LDM
    answers;
  - `object_count`: exact match and absolute error;
  - labels: CER/WER (atrium-project#22's `eval_metrics` can be reused), plus KV field F1;
  - terms: precision/recall against the gold terms;
  - `objects`: IoU-matched precision/recall per term, and mAP where scores exist;
  - operational figures as in Phase E.
- **Invalid JSON** is counted as a failure, not repaired silently.

### Phase I: hardware sizing

- **Spark-class unit:** 128 GB unified memory (two can be linked), ~273 GB/s memory bandwidth. _Check against
  NVIDIA's current specification._ Budget weights ≤ ~100 GB per unit, leaving room for the KV cache and image tokens.
- **The three decision models are small:**
  - Clef ~54 GB in bf16 (the card ran on one H200);
  - Clef-Flash ~18 GB;
  - Strands ~4 GB, which runs on a CPU.
  - A decision model only prefills, so it needs no sampling setup.
- **Track-2 VLM shortlist, to verify at run time** (weights ≈ parameters × bytes per parameter): Llama 4 Scout 109B
  MoE (FP8 ~110 GB), GLM-4.5V 106B MoE (FP8 ~106 GB), Qwen3-VL-235B-A22B (4-bit ~120 GB+, two units or tight),
  InternVL3.5-241B-A28B (4-bit ~125 GB+, two units).
- **The internal endpoint (11-06)** is a Mac-class machine. It serves the 8-bit Clef beside a generative model
  (`Qwen3.8-Flash-Next-oQ8e-mtp`). Its throughput under that shared load is measured in Phase A, not assumed.
- **Larger models** (e.g. MiniMax-M3-MXFP8) go to the Grace Hopper machine via Viktor, as stranak noted on
  atrium-project#22 (06-19).
- **Per model, record:**
  - whether it loads;
  - the quantisation and its quality cost (a small dev comparison against a higher precision where it fits);
  - the time per image;
  - the memory headroom.

## The other three repositories (summaries; the plans hold the detail)

Each has an issue of its own (to be opened, drafts of 11-06), under the hub umbrella.

**ocr-postprocess:** decision models on ambiguous lines, in shadow mode.
- **Which lines:** a deterministic selector picks the lines the rule cascade is least sure of:
  - short lines without Czech diacritics (gate 6);
  - red flags that fired without a conviction (gates 9a–9f);
  - the band edges at 0.55;
  - foreign lines read `Noisy`;
  - lines a document pass overrode.
- **The question:** a `choice` over `Clear`, `Noisy`, `Trash`, `Non-text`, with the vocabulary's definitions.
- **Where answers go:** a sidecar table. `categ` and the record stay untouched.
- **How it is judged:** scored on the 2,067-line gold set with the repository's own adoption gate. The categories stay
  frozen until after the pilot (atrium-project#67).
- **Models:** text only, so Strands Decider 2B is the cost target there.
- **Which stage to call next** stays a rule over counts, outside the tool.

**digital-convert:** a type per PDF page and per document, from the rendered page and its text.
- **The options:** AMČR's heslář `dokument_typ`, 32 of its 41 terms (with `api.aiscr.cz` URIs); `neurčený dokument`
  abstains.
- **Where it appears:** in the `/describe` report and the CLI, behind a flag.
- **The record:** unchanged until a `document-type` scheme is agreed with AMČR and atrium-project#71 grants a field.
- **Gold:** each sample PDF's catalogue type (document level) and 300 annotated pages.

**keyword-extract:** the controlled kind's category, chosen by descending the vocabulary (keyword-extract#2).
- **The descent:** meta-text, then facet (10), then group (1–25 per facet), then down the terms' own tree (up to 11
  levels; its parents are the nearest offered ancestors of `specificity_pairs.csv`).
  - Each step is a `choice` of at most 255 options, plus `<this term>` where the node is a term, plus
    `none_of_these`.
  - Only one node, `historické oblasti a státní útvary` (~260 children), is chunked.
- **Why it fits #2's ruling D2** (a validated term or unresolved): the model cannot answer outside the list.
- **Why it reaches everything:** the whole vocabulary is reachable at any window, where the 58,260-token generative
  prompt reaches ~1,100 of the 4,711 terms at 16k.
- **The comparison:** Clef shares Qwen3.8-27B with #2's default model.
- **Scored:** without gold by `score_categories.py` beside #2's runs; with gold, under D1 and D2.
- **Not covered:** keywords (spans) stay generative or statistical.

## Phase J: record the outcome

Write one report per repository, under `agent_dev_logs/` or an experiment directory. Each has:
- commands or a runnable script, the question sets and their digests, the pinned revisions;
- the split manifest and the gold checksum;

- **Keep as a research option:** useful for a narrow class, a route or a field.
- **Propose a follow-up**, each as its own reviewed task. For example:
  - the cascade as an optional `--decide-below τ` and a `decide` form field;
  - a record block for image descriptions and segments (atrium-project#71, shared with #22's region check);

- [ ] `decision_client.py` exists with its selftest; the three consumers pin their copies.
- [ ] Each candidate's server is recorded and answers the card's request and one page image, or is ruled out with a
      reason. Clef is probed on the internal endpoint first: route, build, images, reach and latency.
- [ ] B1, B2 and B3 are scored on the fold-1 test partition against `v1.4` and `v4.4`, with τ and the lanes frozen on
      dev, the unseen-document subset reported and every failure recorded.
- [ ] The track-2 schema, prompt and `capture_context` list are written and reviewed with a domain annotator.
- [ ] A track-2 gold set exists, or its absence is documented as the blocker.
- [ ] Track-2 fields are scored with and without the linked document.
- [ ] At least one Spark-class-sized model has been sized and tried, or ruled out with a reason.
- [ ] Results and limits are reproducible from the recorded artefacts; nothing in production changed.

## Out of scope

- Reordering or changing `model_registry.CATEGORIES`, or relabelling checkpoints.
- LDM or VLM inference in the production API or image, or a change to the classifier default.
- A record schema change for routes, descriptions, segments or document types (propose under atrium-project#71 if
  the evidence supports it).
- Fine-tuning (including Cloudflare's RL tuning service) before a zero-shot result justifies it.
- A large re-annotation campaign before the small gold set shows the fields are useful.
- Sending archival images to hosted inference without approval.
